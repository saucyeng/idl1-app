# C6 — CLI surface

**Status:** draft (cli-verbs lane) 2026-09-11 · **Date:** 2026-09-11 · **Owner:** lead

The `idl-rs` command-line surface: its grammar, its closed vocabularies, the
behaviour every command shares, and the one table all of it is generated
from. Rulings R230 (architecture) and R229 (the verbs to add) are the
authority; this section records what landed.

The generated reference — `docs/CLI-REFERENCE.md`, written by
`idl-rs docs cli --out` — is the per-command documentation and is not
duplicated here. This section is the contract the reference is generated
under.

---

## 1. Grammar

```
idl-rs <noun> <verb> [args] [--flags]
```

A command is a noun and a verb. Nothing else: there are no noun-less verbs
in the current surface, and no flag that selects between two different
operations.

### 1.1 Nouns (closed, R230)

`session`, `workbook`, `track`, `catalog`, `library`, `device`, `docs`.

`device` is reserved for the transport lane and has no rows yet. An empty
noun is not a failure; a noun outside this list is.

### 1.2 Verbs (closed, R230)

`list`, `show`, `new`, `check`, `eval`, `set`, `import`, `export`, `scan`,
`fold-in`, `index`, `rebuild`, `verify`, `delete`.

A verb outside this list needs a ruling. The verbs a ruling has since added
are recorded with that ruling, in `idl_rs::commands::table::VERBS_RULED`:

| Verb | Ruling | Why |
| --- | --- | --- |
| `set-start` | R229 | Setting a recording start is not the same operation as setting metadata, and `set` alone could not say which |
| `set-meta` | R229 | As above |
| `cells` | R229 | Listing a workbook's cells is not `list` on the `workbook` noun, which would read as "list workbooks" |
| `data` | R229 | Printing one cell's samples |
| `detect` | R229 | Lap detection is a computation, not an `index` of existing values |
| `laps` | R229 | A session's laps are a named sub-collection, like `cells` |
| `stale` | R197 | Shipped with the `library` group; R229 keeps the existing `library` verbs' names |
| `wire` | R236 | `docs wire` emits the binary-format golden fixtures the app's decoders are tested against; not a `list` of anything |
| `workbook` | R222 | Shipped as `docs workbook` |
| `cli` | R230 item 2 | Written out in the ruling itself |
| `synth` | R187 | Generating a session is not `new` (which makes an empty artifact) and not `import` (which reads one); the synthetic generator is the roadmap's own firmware-precondition item, and its brief grants the verb |

A test enumerates every row and fails on a noun or a verb outside both
lists. Adding a verb therefore means editing `VERBS_RULED` and naming the
ruling that allowed it.

### 1.3 Legacy commands

The pre-R230 noun-less verbs (`info`, `channels`, `export`, `math`, `laps`,
`fft`, `spectrogram`, `visits`, `fit`, `recover`, `scan`, `table`, `import`,
`sessions`, `verify`, `prune`, `rescan`) still run. R230 allows breaking
changes only at a major version. They are not in the table — the grammar has
no place for them — and the ones a table row supersedes print a one-line
notice to **stderr** naming the replacement, leaving stdout byte-identical
for a script that has not been updated yet:

| Legacy | Replacement |
| --- | --- |
| `import` | `session import` |
| `sessions` | `session list` |
| `verify` | `catalog verify` |
| `rescan` | `track detect` |
| `table eval` | `workbook eval` |
| `table list` | `workbook cells` |
| `table check` | `workbook check` |

`info`, `channels`, `fft`, `spectrogram`, `math`, `fit`, `recover`, `scan`
and `prune` have no noun-rooted replacement yet and are not deprecated.

## 2. The one command table

`rust/core/src/commands/table.rs`. It is in `core`, not `cli`, for two
reasons: it is pure data, so it breaks none of CLAUDE.md §2's purity rule;
and `idl-rs-tauri` needs the same rows to derive R228 item 2's agent tool
schemas, which it cannot take from the CLI binary.

### 2.1 Row shape

| Field | Meaning |
| --- | --- |
| `noun` | A member of §1.1 |
| `verb` | A member of §1.2 |
| `args` | Positional arguments in order: name, value kind, required, repeatable, choices, help |
| `flags` | The command's own long flags: name, value kind (or switch), repeatable, choices, default, help |
| `core_fn` | The `idl_rs` path of the function that does the work |
| `json_shape` | The name of the shape `--json` emits — the C3 DTO's name where one exists — or absent when the command writes an artifact instead of a payload |
| `help` | One line, sentence case, no trailing full stop |
| `tier` | `core` / `occasional` / `rare`, the same union as the app's `commandTiers.ts` |
| `status` | `current` or `deprecated` |
| `data_dir` | The command works against a data directory |
| `writer` | The command writes |

`data_dir` and `writer` are declarations of what the command *is*; §3's
uniform flags are materialised from them rather than repeated on each row.

### 2.2 Generation

- The clap subcommand tree is built by walking the rows. A command is
  declared in exactly one place.
- `idl-rs docs cli --out <file>` renders the table as Markdown
  (`docs/CLI-REFERENCE.md`).
- `idl-rs docs cli --json --out <file>` renders it as JSON
  (`app/src/shell/cliTable.json`), checked in and regenerated by CI, which
  fails on a diff — the same arrangement `docs/WORKBOOK-REFERENCE.md` uses.

### 2.3 Agreement with the app's table

`app/src/shell/commandTiers.ts` stays the UI's table. The two overlap rather
than match: the UI has `view.*` and `go.*` entries with no CLI counterpart,
and the CLI has `catalog verify` with no button. A row's shared id is
`noun.verbInCamelCase` (`workbook.new`, `library.foldIn`), and a test in
each repo asserts that the two tables agree on the ids they both name, and
that the shared set is not empty.

Where a shared id's tier is ratified on the app side (R225), that is the
tier — `workbook.new` and `library.rebuild` are `occasional` in both tables
because R225 put them there.

This is the seed of R228 item 2's agent tool schemas. The schemas are not
built yet.

## 3. Uniform behaviour (R230 item 3)

Every command in the table:

- **`--json`.** The payload is the C3 DTO where one exists, wrapped in an
  envelope carrying `schema_version: 1`, `ok`, `command`, `engine` and
  `data`. Success goes to **stdout**; a failure goes to **stderr** as the
  same envelope with `ok: false` and a typed `error` instead of `data`, so
  a consumer reading stdout never has to distinguish the two shapes. (The
  pre-R230 commands in `cli/src/envelope.rs` put structured errors on
  stdout; that is the older contract and is unchanged.)
- **`--data-dir`**, on every command whose row sets `data_dir`. Falls back
  to the `IDL1_DATA_DIR` environment variable. Neither set is a usage
  error naming both.
- **`--dry-run`**, on every command whose row sets `writer`. The command
  reports what it would change and writes nothing.
- **Exit codes.** `0` success, `1` a failed operation, `2` a usage error.
- **Idempotence** where the operation allows it. `session set-meta` writes
  only the fields whose value actually changes, and writes nothing at all
  when none does.

A row may not declare a flag named `json`, `data-dir` or `dry-run` itself; a
test enforces it.

## 4. Verbs

### 4.1 `session`

| Command | Notes |
| --- | --- |
| `session list` | Filters `--venue --track --since --until --tag`. `--track` is the one filter the catalog cannot answer — track visits live in `session.json` — so it costs one file read per row and is applied last, over the already-narrowed set. A session whose start is `0` ("unknown", C1 §3.1) is dropped by any time bound rather than treated as 1970. |
| `session show <id>` | |
| `session laps <id>` | |
| `session set-start <id> <utc-ms>` | |
| `session set-meta <id>` | `--venue --rider --bike --event --event-session --notes --tag`. `--notes` writes `session.json`'s `long_comment`. An empty string clears a field, which is how C1 §6 spells "not set". |
| `session import <file>` | |
| `session synth` | `--out --laps --lap-length-m --rate-hz --gps-hz --seed --noise --imu-count`. Writes a real `.idl0` log plus a `<out>.truth.json` ground truth beside it; contract C1 §9 is the whole specification. Takes no `--data-dir`: it writes a log file, and importing it afterwards is `session import` like any other. `--noise` is `text` rather than an integer because the table has no floating-point value kind. |

**There is no `--track` on `set-meta`.** A session's track association is
detected from its GPS (`track detect`), never typed in; a user-supplied
track string would be a second source of truth for something the engine
already computes. R229's `--track` in the `set-meta` list is read as the
`session list` filter of the same name.

### 4.2 `workbook`

| Command | Notes |
| --- | --- |
| `workbook new <file>` | `--template blank\|session`, `--session <id>`. Refuses to overwrite an existing file. |
| `workbook check <file>` | Structure always; evaluation too when `--session` is given. |
| `workbook cells <file>` | |
| `workbook eval <file> --session` | |
| `workbook data <file> <cell> --session` | |
| `workbook export <file>` | `--out`, `--format md\|json`. |

**Laps: `--track` and `--main-lap` travel together.** `--track` detects the
session's laps and sectors. `--main-lap <n>` names the 1-based lap a
lap-scoped expression means. There is no default, and the absence of one is
not harmless: `main_lap_window` treats an unset main lap as "no window
selected" (R128), so every scalar aggregate a cell scoped to the main lap —
`mean()`, `max()` — reads the **whole session** instead. A `.idl0` file
carries no designation (that lives in a data directory's `session.json`) and
defaulting to lap 1 would answer a question nobody asked, so the command
instead prints a one-line note to stderr saying lap-scoped expressions are
reading the whole session. `--main-lap` naming a lap the session does not
have is a `not_found` error listing the ones it does; `--main-lap` without
`--track` is a usage error. The context is assembled in
`idl_rs::commands::lap_ops`, so every headless caller fills all four of its
fields the same way. `baseline_row` stays unset: it is a table's Main *row*,
not a lap, and `main()` is `NaN` without it.

**`js` cells are not evaluated.** A `js` cell runs in the app's sandboxed
webview, and `core` has no JavaScript engine — by CLAUDE.md §2 it never
will. `workbook eval` and `workbook export --format json` report such a cell
as `evaluated: false` with the reason, rather than silently producing
nothing; `workbook data` on one is an `unsupported` error.

**Templates.** R225 ratified that there is no template *concept* yet. A
template here is a named starting document, nothing more: a closed value
list on the row, so adding one is a new value rather than a new verb.
`blank` is front matter and a title; `session` adds a worked `math` cell to
edit. Both are round-tripped through the workbook parser by a test, so a
skeleton that would not parse fails the build rather than the user.

**`--report` is not implemented.** R229 lists `report <file> --out`, which
this section would spell `workbook export --report <out.html>`. There is no
Rust HTML report renderer: the renderer is TypeScript
(`app/src/routes/pages/Notebook/model/report/document.ts`) and needs the
JS and chart cell outputs only the sandbox can produce. A Rust `--report`
would either duplicate that pipeline or silently drop every JS and chart
cell. The row is therefore not registered, and `workbook export` offers
`md` and `json` instead. **Open:** a Rust report renderer, or an
`--report` that shells out to the app.

### 4.3 `track`, `catalog`, `library`, `docs`

| Command | Notes |
| --- | --- |
| `track list` | |
| `track detect <id>` | The noun-rooted spelling of legacy `rescan`; the same `lap_index::reindex_laps`. |
| `catalog verify` | Exits `1` when any finding is error-severity, with the findings in the error's `details`. |
| `catalog rebuild` | |
| `library fold-in \| scan \| stale \| index \| rebuild` | R197's verbs, names unchanged. Declared by the table; the existing renderers in `cli/src/library.rs` are reused verbatim. |
| `docs workbook` | R222's; renderer reused verbatim, so the byte-stability CI depends on has one implementation. |
| `docs cli` | Emits this table. |

`library index` and `library rebuild` have no read-only form in the engine,
so their `--dry-run` reports the intent rather than half-running the job.
The same is true of `track detect` and `catalog rebuild`.

Dry runs are therefore not uniform in how much they validate. Where the
engine validates an argument before writing, the dry run validates it too —
`session set-start --dry-run` still rejects a non-positive timestamp. Where
the only validation is inside the write itself, the dry run reports the
intent and checks nothing: `library index`/`rebuild --dry-run` do not verify
that the session ids exist. The rule is that a dry run never writes, not
that it predicts every failure.

## 5. Open questions

1. A Rust HTML report renderer, so `workbook export --report` can exist
   (§4.2).
2. `device` has no rows. The transport lane owns what they are.
3. `delete` is in the closed verb vocabulary and no row uses it. The
   deletion paths (`catalog::delete_session`, `delete_track`) are reachable
   from the app but not the CLI.
4. CI does not yet regenerate `docs/CLI-REFERENCE.md` and
   `app/src/shell/cliTable.json` and fail on a diff. The release-ci lane
   owns the workflow; the commands are
   `idl-rs docs cli --out docs/CLI-REFERENCE.md` and
   `idl-rs docs cli --json --out app/src/shell/cliTable.json`.

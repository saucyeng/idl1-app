## Named-risk checks

### 1. Burst-seam worked example — arithmetic reproduced, matches

Inputs: `nominal_period_us = 1_000_000/800 = 1250`; true period `1200 µs`; `N=4`/burst;
`T_0=100000, T_1=104800, T_2=109600, T_3=114400`.

Recorded stamps (`stamp[i] = T_k − (3−i)×1250`):
- burst0: 96250,97500,98750,100000 — doc matches.
- burst1: 101050,102300,103550,104800 — doc matches.
- burst2: 105850,107100,108350,109600 — doc matches.
- burst3: 110650,111900,113150,114400 — doc matches.

Seam deltas: `101050−100000=1050`, `105850−104800=1050`, `110650−109600=1050` — all outside the
±1 µs tolerance of 1250, so 4 bursts of N=4 correctly detected. Matches doc.

Effective-period estimates (`(T_k−T_{k−1})/4`): `1200, 1200, 1200` → median `1200 µs`. Matches
doc exactly (true period recovered).

Re-spaced (`corrected[k][i] = T_k − (3−i)×1200`), session-wide period applied to every burst
including burst 0:
- burst0: 96400,97600,98800,100000
- burst1: 101200,102400,103600,104800
- burst2: 106000,107200,108400,109600
- burst3: 110800,112000,113200,114400

All match the document exactly. Every consecutive delta, including across all three seams
(`101200−100000=1200`, `106000−104800=1200`, `110800−109600=1200`), is exactly 1200 µs —
strictly increasing. Each burst's last sample equals its own `T_k` (offset 0 at `i=N−1`),
satisfying "ends each burst at its read instant." Monotonicity pre-check
(`T_k−(N_k−1)×1200 > T_{k−1}`) holds cleanly for all three seams (101200>100000, 106000>104800,
110800>109600) — no local-period fallback triggers in this example, consistent with the doc not
invoking it here.

Subtracting the session minimum (`96400`) reproduces the document's final `t_us` list exactly:
`0,1200,2400,…,18000` (16 values, step 1200). **Recomputed independently — the example
reproduces bit-for-bit.**

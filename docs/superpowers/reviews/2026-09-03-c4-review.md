#### Important

| Severity | Location | Finding | Fix |
|---|---|---|---|
| Important | C4 §1, "Override in Settings" | **Verified against the pinned `tauri-2.11.5` crate source** (`~/.cargo/registry/cache/.../tauri-2.11.5.crate`, extracted locally — the exact version C4's own front matter cites): `src/path/desktop.rs` defines `app_config_dir()` as `dirs::config_dir().join(bundle_id)` and `app_data_dir()` as `dirs::data_dir().join(bundle_id)`. In `dirs-6.0.0/src/win.rs`, both `config_dir()` and `data_dir()` call the identical `dirs_sys::known_folder_roaming_app_data()` — same path. In `dirs-6.0.0/src/mac.rs`, both call the identical `app_support_dir()` (`~/Library/Application Support`) — `preference_dir()` is a distinct, unused function returning `~/Library/Preferences`. So on **both Windows and macOS**, `app_config_dir() == app_data_dir()` byte-for-byte; they diverge only on Linux (`dirs-6.0.0/src/lin.rs`: `XDG_CONFIG_HOME` vs `XDG_DATA_HOME`). C4 §1's claims that (a) the bootstrap file is "independent of `<data>`" and (b) macOS's `app_config_dir` is `~/Library/Preferences/<bundle-id>` are both factually wrong for this dependency version. On Windows/macOS — the two platforms D5 calls "the comfortable authoring surface" — `settings.json` lands inside the live default `<data>` tree, undisclosed in §2's Layout, contradicting the section's own stated rationale for needing a separate location at all. | Pick a location genuinely outside `<data>` on all platforms (e.g. `app_local_data_dir()` + a fixed subpath, or a path next to the executable) — do not rely on `app_config_dir`/`app_data_dir` divergence, since it doesn't exist on Windows/macOS in this crate version. Correct the macOS resolver description from `Preferences` to `Application Support`, or drop the specific path claim if a different location is chosen. |

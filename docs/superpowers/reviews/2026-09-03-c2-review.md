## Spec Compliance — checklist (a)–(e)

**(a) the worked example from design §5 parses under §2–§5 as written.**
⚠️ Partially met, honestly disclosed rather than silently claimed.
Verified: the design §5 example, taken *literally* (`deriv(fork_travel, t)`,
unbracketed `fork_travel`, elided `id: 9f3c…`, no `id=` fence attrs, no
`version` key), does **not** parse under the drafted grammar — `deriv` is not
in §3.3's catalog, bare `fork_travel` fails §3.2's bracket rule, and unfenced
ids are illegal past first save (§2.2). The document does not paper over this:
§2.5 states the mismatch and gives a corrected, byte-for-byte example that
*does* parse under §§2–5 as drafted, with every substitution traced to the
specific rule it satisfies (checked by hand: front matter valid, both
`def_line`s match §3.1/§3.2 and use only §3.3 catalog names, the `js` cell
matches §5.3 Example 1 exactly, the `${…}` matches §5.2). This is the
"section states its own values, doesn't defer" case the task explicitly
credits over deferral — but the literal checklist wording ("the worked
example ... parses ... as written") is not met by the design doc's own prose
form, only by a substantively rewritten stand-in. Rated ⚠️, not ❌, because
the deviation is named, justified per-token, and does not leave any value
unstated.

**(b) §5.3 examples round-trip conceptually (props → code → props).**

**(e) §3.3 lists every function in idl0's `MathChannel.knownFunctions`.**
✅ for coverage, ❌ for the arithmetic self-check. Enumerated
`MathChannelValidator.knownFunctions` in `math_channel.dart` directly: 48
entries. All 48 appear in the §3.3 table (verified name-by-name against the
document's own cross-check list at lines 394–403, which is itself correct).
However, the document's headline count — "70 named functions total (54
Implemented, 6 NotImplemented...)" — is wrong on both numbers. Counting the
document's own table rows (lines 326–383, expanding multi-name rows like
`floor` `ceil` `round`) yields **69** distinct function names, not 70; of
those, 6 are `NotImplemented` (`sosfilt`, `spectrogram`, `hilbert`,
`correlate`, `convolve`, `resample` — all verified against real
`NotImplemented`-returning arms in `eval.rs`), so the `Implemented` count is

`detrend` mode validation, `deg2rad`/`rad2deg` real trig-conversion bodies,
`p`/`atan2`/`clamp`/`if`/`main` bodies — all match `eval.rs` exactly), so this
is a self-check arithmetic error, not a coverage or mis-marking defect. Flagged
under Important below since checklist (e) and named risk 1 both turn on this
document's own count being trustworthy.

- **Missing from doc:** none. All 48 `knownFunctions` names present.

  `Implemented` row against `eval.rs` `call_function`'s top-level match arms
  (8-space-indented arms only, to exclude nested sub-matches like `butter`'s

  plausible miss ("known to validate in Dart but have no evaluator arm") —

  "sosfilt" => Err(... NotImplemented ...)`), which does nothing but return
  the typed error — correctly represented.

  named functions total") is wrong (see checklist (e) above) — 69 actual,
  63 Implemented not 54.

**2. `plotForm` grammar reproduces its own examples.**
All three examples derive from the §5.3 EBNF (detail under checklist (b)).
Grammar productions **no example exercises**:
- `x_field ::= "type": "\"linear\""` — no example sets `x.type` (the document
  itself flags this as provisional in Open Question 2, so this is a disclosed
  gap, not a silent one).
- `x_scale`'s `domain` field — no example sets `x.domain` (only `y.domain` is

every example that exists derives correctly — but the brief asked the
grammar and examples to mutually justify each other, and roughly half the
grammar's surface (all of `x`'s fields, 3 of 5 mark kinds) is asserted but
never demonstrated.

## Spec Compliance — checklist (a)–(d)

**(a) every command has typed args and return — ✅ (with 2 minor gaps, not failures)**
All 23 commands across §3.1–§3.9 (`engine_version`, 5 catalog, 2 import, 4 workbook, `fetch_tile`, `fetch_raster`, `cursor_readout`, 5 device, 3 sync) have TS-typed argument lists (either inline in the `command(arg: type, …)` signature or an explicit `Args: none.` line) and typed returns (named `interface`s or a primitive). Verified by reading all of §3 in the diff.
⚠️ Two inconsistencies, not omissions: `list_workbooks()`/`list_tracks()` show empty parens but skip the `Args: none.` line other zero-arg commands (`list_sessions`, `rebuild_catalog`, `list_importers`, `sync_status`) use — inconsistent, not wrong. `watch_workbook` never states a `Return:` value (only "the command's own `Promise` resolves once subscription is established"); every other command explicitly types its return, even `void`-returning `push_config` (`Return: void (resolves with no value on success)`). Doc lines: `docs/superpowers/specs/2026-09-03-idl1-c3-ipc-surface.md` §3.2 `list_workbooks`/`list_tracks`, §3.4 `watch_workbook`.

**(b) §3.5 byte offsets sum correctly for tier 3 / 512 samples / 256 columns — ✅, independently re-derived**
Header 32 bytes fixed (magic 4 @0, version u16 @4, tier u16 @6, tile_index u32 @8, sample_count u32 @12, column_count u32 @16, flags u32 @20, reserved 8 @24 → ends @32) — matches the brief's exact header layout field-for-field and offset-for-offset.
Sample region: `32 + 512×2×4 = 32 + 4096 = 4128`.
Column region: `4128 + 256×3×4 = 4128 + 3072 = 7200`.
Total = `32 + 4096 + 3072 = 7200` bytes — matches the brief's worked-example total exactly. Raster layout (§3.6) is likewise correct: header 16 bytes (magic 4, version u16, width u16, height u16, format u16, reserved 4 → 4+2+2+2+2+4=16), pixel region `width×height×4`; 64×32 worked example gives `16 + 8192 = 8208`, correct.

**(c) §2 `kind` list includes every `TransportErrorKind` value — ✅, verified against source, not the report**
Read `rust/transport/src/error.rs` directly (via `git show 05e463e:transport/src/error.rs` in the idl0-app rust submodule's object store, since the c3 worktree's submodule isn't checked out). `TransportErrorKind` has exactly 4 variants, `#[serde(rename_all = "snake_case")]`: `Ble`, `Wifi`, `Config`, `Sync` → `ble`, `wifi`, `config`, `sync`. All four appear verbatim as the first four rows of §2's kind table, unprefixed, with the documented rationale (already a shipped, tested contract from Task 2). Match is exact.

**(d) no placeholders — ✅**
`grep -ni "TBD|TODO|decide later|FIXME|XXX"` over the full diff: zero hits. Every place a detail isn't pinned by an upstream source is written as a numbered, owned open question in §6 (lead/L2/L3/L4 assignments, all with what would resolve them), not an inline placeholder. `**Status:** draft` is present verbatim at the top.

- `ConfigErrorKind`: `Io`, `Parse`, `UnsupportedVersion` — all 3 present (`Io` folded into `io`). ✅
- `ExportError`: `UnknownChannel`, `Io(io::Error)`, `Json(serde_json::Error)` — all 3 present (`Io` folded into `io`, `Json` folded into `internal`, both stated explicitly). ✅
- `FitExportError`: `NoGpsData`, `Io(io::Error)` — both present (`Io` folded into `io`). ✅

Did not diff its variants since the enum itself is out of scope by design decision, not oversight.

**No missing enum and no missing variant.** The named risk does not materialize — every core error enum variant either has a row or an explicitly-stated fold into `io`/`internal`.

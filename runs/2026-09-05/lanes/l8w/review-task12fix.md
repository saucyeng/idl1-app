## Checks performed (all pass)

- **`none` > 1 segment ⇒ `invalid_argument` with `detail.segments == n`, exact JSON shape.** `check_none_averaging_segments` (`core/src/fft.rs:166-181`) returns `FftError::NoneRequiresOneSegment { segments }` when `segment_count(...) > 1`; `map_fft_error` (`tauri/src/commands/rasters.rs`) maps it via `IpcError::with_detail(IpcErrorKind::InvalidArgument, ..., serde_json::json!({ "segments": segments }))`. `IpcErrorKind` is `#[serde(rename_all = "snake_case")]` (`tauri/src/error.rs:15`), so `InvalidArgument` serializes to `"invalid_argument"`; `detail` serializes as `{"segments": <number>}` — byte-exact against C3 §3.6's amended sentence (`docs/superpowers/specs/2026-09-03-idl1-c3-ipc-surface.md:1042-1043`, "`invalid_argument` with `detail: { "segments": n }`") and against C3 §2's generic error shape. Confirmed by the new test `fetch_fft_via_averaging_none_with_multi_segment_window_invalid_argument_with_segment_count` asserting `err.detail == Some(json!({ "segments": 7 }))`.
- **`none` with exactly one segment ⇒ output byte-identical to before, and this is pinned by a test.** `check_none_averaging_segments` is `Ok(())` whenever `segment_count(...) <= 1` (i.e. `Averaging::None` with `nperseg` covering the whole record, or any non-`None` averaging). The rewritten test `fetch_fft_via_averaging_none_full_record_window_and_max_succeed_and_produce_well_formed_idlf_bytes` explicitly forces `window_size: 128` (the channel's full 128-sample length) for the `none` case, distinct from `max`'s `window_size: 32`, and asserts a well-formed `IDLF` header — this is the single-segment path, and `Averaging::None`'s reduction arm (unchanged by this diff, still `seg_powers[0][k]`) is now provably correct because there is provably only one segment. No behavioural change to the byte encoding itself in this diff (only validation was added ahead of the existing call); the `fft.rs` unit test `welch_averaging_none_single_segment_matches_averaging_mean_single_segment` independently pins that `None`'s single-segment output equals `Mean`'s (trivially true with one segment), guarding against a future regression in the reduction arm.
- **`segment_count` arithmetic agrees with `welch`/`stft`'s actual segmenting.** `segment_count` (`core/src/fft.rs:130-146`) is a line-for-line mirror of `stft`'s own loop (`core/src/fft.rs:338-364`): same `resolve_seg`, same `overlap = if noverlap >= seg { seg - 1 } else { noverlap }`, same `step = seg - overlap`, same `while start + seg <= n { ...; start += step }` counting loop. Hand-computed the test's own example (128 samples, `nperseg=32`, `noverlap=16`): `resolve_seg(32,128)=32` (32≠0, 32<128); `overlap=16` (16<32); `step=16`; start values `0,16,32,48,64,80,96` all satisfy `start+32<=128` (start=112 fails, `144>128`) → 7 segments — matches the test's asserted `Err(FftError::NoneRequiresOneSegment { segments: 7 })` and the reused `fft_params()` fixture (`window_size: 32, hop_size: 16`) in `fetch_fft_via_averaging_none_with_multi_segment_window_invalid_argument_with_segment_count`.
